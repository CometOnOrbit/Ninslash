# Ninslash 可玩性设计：挑战模式 / 种子分享 / PvP 平衡 / 观战增强

> 目标（EA 前）：提升可复玩性（每天想再玩一局）、内容量、PvP 竞技性（平衡 + 体验）。
> 原则：社区驱动（官方提供机制，内容由社区创造）；不做官方每日挑战、不做 PvP 排位、
> 不做外观解锁；Forge 是 PvP 特色玩法必须保留。
> 状态：设计蓝图（未实施）。

---

## 1. 设计目标与原则

- **可复玩性三支柱**：局内多样性（程序化地图/任务/变体）、局外钩子（研究点奖励/好友排行）、
  对抗深度（PvP 平衡 + 观战体验）。
- **社区驱动**：挑战码可分享、变体可 Lua 扩展、种子可分享——官方只搭机制。
- **Forge 保留**：Forge 是 Ninslash 差异化玩法，PvP 中保留（平衡靠数值调整，不移除/不切换武器池）。

---

## 2. 挑战模式（规则变体 Modifier）

**定义**：可叠加的规则修改器，改变单局玩法（类似 Halo skull / Risk of Rain artifacts）。
与"种子分享"（同图竞速）是两个独立功能，可独立用、可叠加用。

### 2.1 变体分类（三层实现）

| 层 | 机制 | 示例 |
|---|---|---|
| 参数层 | 启动时批量覆盖 `sv_*` / 数值参数 | 低重力、敌人×2、伤害×2、血量减半、无建造 |
| 生成层 | 确定性 PRNG + 生成钩子（敌人/掉落/事件） | 全 Droid、全 Boss、精英化、无远程、敌人×2 |
| 逻辑层 | 代码 / Lua 钩子 | 只有 XXX（锁定武器）、无 Forge、黑暗视野（渲染） |

- **叠加上限 3 个**（防不可玩组合爆炸）。
- 敌人类变体：改生成逻辑（`invasion.cpp`/`extract.cpp`/`horde.cpp` 的波次/事件抽取走确定性流）。
- 环境类变体：纯数值覆盖（启动时写配置），最易实现。
- 武器类变体：
  - **静态武器（`SW_*`）不参与 Forge**——既有代码层硬规定（`forge.cpp` 的 modular 判定），保持不变。
  - **"只有 XXX" = 玩家只能持有 XXX 武器**（基础/静态武器池锁定一种，Forge 合成不可用）。
- 黑暗视野等**渲染类变体**也做（EA 前）：视野收缩、低光滤镜（客户端渲染钩子）。

### 2.2 适用模式

- 所有模式可加变体，**排除 Ball、Roam 小游戏模式**。
- PvE（Invasion / Extraction / Horde）：全类别可用。
- PvP 自定义房间：武器类/环境类可用（如无 Forge、一命、武器池限定）。

### 2.3 挑战码

- 格式：`模式-难度-种子-变体组合(≤3)`，如 `INV-15-1234567-D3C1`。
- 变体字母编码：`D`=敌人类、`W`=武器类、`E`=环境类，后接序号。
- 同码 = 同模式/难度/种子/变体 → 才可比成绩（与种子分享的"同种子比较"逻辑一致）。

### 2.4 排行榜（本地 + Steam Friends 数据共享）

- 成绩带**变体签名**存储；同签名组合才比较。
- **本地历史**（本地存档）+ **Steam Friends 数据共享**（好友间互传成绩，
  复用云存档三路决策的传输通道思路，见 `pve_progress_storage` / `cloud_profile`）。
- 不设全球榜（社区驱动：好友间竞争 + 分享码自组织）。

### 2.5 首次通关奖励（局外钩子）

- 每个变体组合**首次成功 + 研究点**（一次性）。
- 记录在 `pve_progress.json`（防刷）。
- 目标：驱动玩家"每天试新组合"。

### 2.6 社区扩展

- **Lua 变体**：数据 + 简单逻辑（仿武器 Lua 运行时 `weapon_script_runtime`）。
- **服务端代码**：高级变体（编译扩展）。
- 官方内置一批变体（EA 前交付）。

## 3. 种子分享

### 3.1 种子上限：int 安全

现状：`sv_mapgen_seed`（config_variables.h:315）与 `cl_local_server_seed`（:482）上限
均为 32767（2¹⁵−1，历史 16 位限制）。标准 `srand()` 接受 32 位，seed 只作为本地服务器
配置传递（menus.cpp:2741 命令行参数），未进协议/存档——提高无兼容问题。

改动点：
- `config_variables.h:315` `SvMapGenSeed` max → `0x7FFFFFFF`
- `config_variables.h:482` `ClLocalServerSeed` max → `0x7FFFFFFF`
- `menus.cpp:2170 / 2243 / 3526` `clamp(0, 32767)` → `clamp(0, 0x7FFFFFFF)`
- `mapgen.cpp:327` / `invasion.cpp:131` `srand(level + seed)` → `srand((unsigned)seed)`
  （消除溢出；level 并入种子无必要）

### 3.2 确定性内容流 PRNG（方案 A）

- 新增确定性 PRNG（splitmix64/xorshift，跨平台稳定），从 seed 派生、**不碰全局 rand()**。
- 每内容类别独立流：`PRNG(seed, "enemies")` / `"drops"` / `"events"`（seed + 域分隔符哈希）。
- 替换"内容生成"随机源：敌人波次阵容/数量/出生点、掉落生成、任务与事件抽取
  （extract `PickTasks/PickEvent`、invasion Quest 抽取）。
- **保留全局 rand()**：AI 走位、弹道散布、受击反馈等微观行为。
- 效果：同种子 → 地图 + 敌人阵容 + 掉落 + 事件完全相同；AI 微观随机不影响竞速公平。

### 3.3 同码竞速

- 成绩指标：Invasion=到达楼层（耗时决胜）、Extraction=评价+剩余时间、Horde=波数。
- 种子分享与变体可叠加（挑战码含种子与变体）。

## 4. PvP 平衡（平衡 + 体验）

### 4.1 原则

- **Forge 是 PvP 玩法点**：材料资源管理（击杀掉落/地图生成点）→ 合成高级武器 =
  投资风险（合成时机）→ 形成"抢资源 → 合成 → 使用窗口"节奏。
- 不做武器禁用/切换池；做**数值调整层**（保留自由度，校准强度）。

### 4.2 武器数值调整层（数据驱动）

- 在武器 Lua 数据体系（`data/weapons/`）加 **PvP 数值缩放字段**（伤害/射速/弹夹按模式修正）。
- 挂载点：`weapon_behavior` / 武器执行路径读缩放系数（PvP 房间应用）。
- 社区可调（数据驱动，非改代码）；静态武器（`SW_*`）不参与 Forge 的硬规定不变。

### 4.3 模式规则平衡参数表

- 9 个 PvP 模式（DM/TDM/CTF/Ball/BR/Reactor 等）的计分/重生/地图规则参数
  散在各 `gamemodes/*.cpp` → 集中为**每模式平衡参数表**（重生延迟、计分上限、
  bot 强度、随机武器池），数据驱动统一管理，便于平衡调整。

## 5. 观战增强

现状：观战只能旁观玩家视角，无详细数据面板、无镜头控制。

### 5.1 镜头控制

- **自由相机**：RTS 式拖动 + 缩放（地图俯视浏览）。
- **一键跟随指定玩家**。
- **自动导演**：击杀时切到击杀者视角（可选增强）。

### 5.2 观战数据面板

- 所有玩家实时：K/D、当前武器/Forge 组合、连杀、经济/材料。
- 需要：客户端观战 UI + 服务器透传数据（评估现有 snap 覆盖度，缺口补协议字段）。
